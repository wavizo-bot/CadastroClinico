TL;DR
-----
App móvel + web brasileiro, 100% OFFLINE, para profissionais de saúde guardarem e
consultarem fichas de pacientes, território (ruas x equipes) e funcionamento da
unidade. React 19 + Vite + Capacitor (Android) + wrapper C#/WebView2 (Windows/MSIX).
Os dados ficam criptografados (AES-GCM) no IndexedDB local. Não tem servidor, não
tem conta e não envia fichas para lugar nenhum. A internet é usada apenas no
recurso opcional "Importar da URL" (download do arquivo indicado pelo usuário) e
ao abrir links de WhatsApp. É um app PRIVADO/INDEPENDENTE (não é governamental,
não é da prefeitura/PMJ), apesar da origem no contexto "Clínica da Família II".

3. MODELO DE DADOS (client/src/lib/dataStore.ts)
--------------------------------------------------------------------------------
ClinicData = {
  schemaVersion: 1,
  updatedAt: string (ISO),
  databaseDate?: string ("aaaa-mm-dd" local do arquivo de importação MAIS ANTIGO;
                         nunca anda para frente — mantém a menor data),
  territorySeedRevision: 2,
  patients: Patient[],
  territory: TerritoryEntry[],
  unitOperation: UnitOperationEntry[],
  branding?: InstitutionalBranding
}

Patient = { id, registration?, name, mother?, phone?, phones? (8-11 dígitos, até 4),
  address?, cpf?, cns?, cnsExtra?, cnsTodos?[], birth?, sexo?, raca?, etnia?,
  pai?, tags?, healthFlags? }
  - id prioritário: CNS > cadastro > nome|nascimento.

TerritoryEntry = { street, rangeStart?, rangeEnd?, numberRule: "all"|"exclusive"|"even"|"odd",
  exclusiveNumbers?[], team: { name?, color? (HEX), colorName?, textColor?, doctor,
  nurse, communityAgent, assistant? } }
  - numberRule vem dos marcadores da planilha: "!" = lista exclusiva, "@" = pares,
    "#" = ímpares, nada = todos (parseTerritoryRule em territoryRules.ts).

UnitOperationEntry = { title, text }  (setores do "Funcionamento da unidade")

InstitutionalBranding = { displayMode: "pair"|"single", clinicLogo?, cityLogo?,
  centralImage? } — imagens embutidas base64 (png/jpeg/webp, máx 300 KB cada).

PERSISTÊNCIA (dataStore.ts):
- IndexedDB: banco "cadclinico", objectStore "clinic-data".
- Registro cifrado { version:1, salt, iv, ciphertext } na chave
  "cadclinico-local-data-encrypted" (legado: "cadclinico-local-data-legacy").
- Criptografia: AES-GCM-256; chave derivada por PBKDF2 (120.000 iterações, SHA-256)
  a partir da chave LOCAL "cadclinico-local-v1". OBS: essa chave NÃO é a senha do
  usuário — é uma chave fixa do aparelho. A senha de 4 caracteres só controla a
  tela de abertura (barreira de discrição, NÃO criptografia — ver avaliacao-*.md).
- localStorage: senha de acesso em "cadclinico-access-password"; rascunho admin em
  adminStorage.ts.
- base64<->bytes em blocos de 32 KB (leitura 437ms->18ms, escrita 316->201ms).
- loadPersistedData() devolve { dados, erro } (falhas NÃO são silenciosas).

4. REGRAS DE NEGÓCIO CRÍTICAS (o coração do app)
--------------------------------------------------------------------------------
BUSCA DE PACIENTES (Home.tsx + patientSearch.ts):
- Debounce de 2 s antes de pesquisar.
- Prontidão: texto comum >= 4 caracteres; "mãe " (prefixo explícito) busca nome da
  mãe e exige >= 4 chars no termo; consulta numérica < 4 dígitos busca SÓ cadastro;
  >= 4 dígitos busca cadastro, CPF, CNS e telefone; "texto número" = endereço com
  número exato; prefixo de logradouro (rua/av/estrada/travessa) é ignorado na busca.
- Ordem: 1º exato; só se não achar, cai no difuso (Fuse: keys name x3, mother x2,
  address x1; threshold 0.4; minMatchCharLength 3; ignoreLocation; limite 40,
  dedup por id). Índice criado em lazy e resetado quando a lista muda.
- Resultados ordenados alfabeticamente; paginação de 5 pacientes / 10 trechos.
- Acentos são normalizados (NFD + strip) em tudo, inclusive no OCR.

TERRITÓRIO (territoryRules.ts):
- Correspondência por rua (normalizada) + regra de número (intervalo, par/ímpar,
  exclusiva) + especificidade (exclusive=4 > range+par/ímpar=3 > range=2 >
  par/ímpar=1 > todos=0).
- REGRA EXCLUSIVA VARJÃO: "Estrada Municipal do Varjão", "Municipal do Varjão",
  "do Varjão", "Varjão" (c/ ou s/ acento) são o MESMO endereço; exibição
  padronizada = "Varjao".
- REGRA AUGUSTA x DARIO BOCCHINO: números < 3500 (ou sem número) de
  "Augusta Teixeira Rodrigues" convertem para "Dario Bocchino"; >= 3500 mantém.
  Aplica-se em faixas territoriais, endereços de pacientes e importação.

IMPORTAÇÃO DO BI (biImport.ts) — formato ACS Digital:
- 5 tipos de CSV/TSV detectados pelo cabeçalho: s1 "CADASTRO — ANÁLISE DETALHADA",
  s2 "QUESTIONÁRIO AUTO REFERIDO", s3 "SAÚDE — CADASTROS DETALHADOS",
  s4 "CADASTRO — ACOMPANHAMENTO INDIVIDUAL" (raça/cor, situação de rua, doenças
  respiratória/cardíaca, orientação sexual, responsável familiar, etilismo, drogas,
  gestante), equipes (Flor/Cor/Hex/Médica/Enfermeira/ACS + rua + faixa).
- Aceita .csv/.tsv, BOM, windows-1252 (latin1), delimitador detectado.
- UNION-FIND: une registros por CNS + CPF + nome|nascimento; primeiro valor
  não-vazio vence; telefones preenchem slots vazios (até 4); endereços divergentes
  são normalizados e desempatados alfabeticamente (pt-BR).
- CNS: listaCNS() guarda todos os CNS de 10+ dígitos; cnsPrincipal() = "regra do 7"
  (se algum CNS começa com 7, escolhe o MAIOR dos que começam com 7; senão o maior
  de todos). cnsExtra = segundo CNS.
- Telefone: aceita 8 a 11 dígitos (corrigido em 29/09 — antes só 10/11, o que
  causava divergência com o Acompanha Digital).
- Resultado real: 59.422 registros -> 15.741 pacientes em ~423 ms.
- Cadastro Clínico NÃO corta por área geográfica (aceita qualquer endereço); o
  Acompanha Digital SIM (aplicarArea). Por isso a quantidade de pessoas pode diferir
  entre os dois apps — decisão do usuário, não é bug.

MESCLAGEM SEGURA (safeMerge.ts + Admin):
- Princípio: campo vazio na planilha NÃO apaga campo preenchido na base.
- Identificação: CNS > cadastro (real) > CPF (real) > nome+nascimento.
- Valores demonstrativos (troca por real é automática, sem confirmação):
  cadastro 975749, CPF 06626492900, telefones 11978831938 e 1145890208.
- Troca de valor REAL por outro valor real diferente (endereço, nascimento, mãe,
  CNS, equipe...) fica pendente e só aplica após digitar exatamente "CONFIRMO".
- Nome repetido sem identificador confiável: linha NÃO é aplicada.
- Novo trecho territorial só entra com rua + 3 profissionais obrigatórios.
- "Funcionamento da unidade" atualiza direto (sem confirmação).

FAXINA (faxina.ts) — auditoria de qualidade, SOMENTE LEITURA nesta versão:
- 10 grupos: 1 CPF, 2 CNS, 3 Cadastro, 4 Cruzamentos, 5 Identificador+demografia,
  6 Similaridade, 7 Fonética, 8 Inversão/fragmentação, 9 Estatísticas (completude),
  + pipeline de decisão (reclassifica para duplicata quando nome+mae+nasc+endereco
  idênticos).
- Severidades: fraude > duplicata > erro > incompleto > coincidência.
- Motor é um GERADOR com 23 pontos de progresso (executarFaxinaComProgresso) que
  cede ao React a cada etapa (tela repinta 23x; maior bloqueio 166 ms).
  executarFaxina() síncrona devolve o mesmo resultado.
- Complexidade O(n) por chave/hash; limites: LIMITE_BLOCO 40, LIMITE_BLOCO_ID 30,
  LIMITE_BLOCO_NOME_DATA 100, LIMITE_IDS 200, teto LIMITE_ACHADOS 20.000.
- Base real (15.741): 1.796 achados em ~750 ms; 271 duplicatas, 5 erros, 4
  incompletos, 1.516 coincidências, 0 fraudes (import já mergeia CPF/CNS iguais).

BUSCADOR ÓPTICO (ocr.ts):
- Tesseract (ocr/tesseract.min.js, worker compartilhado), extração orientada a
  rótulos de guias/comprovantes; núcleo compartilhado com o Acompanha Digital
  (validado em 48 fotos reais — bancada em ocr_bench/, NÃO editar sem rodar comparar.js).
- Pré-carrega worker ao tocar no botão/abrir tela (evita "initializing api 100%...").
- Ordenação do resultado: 1º cadastro 100% exato (zeros à esquerda ignorados),
  2º similaridade de nome (palavras comuns ponderadas + bigramas/Dice), 3º via
  (Cadastro > CNS > CPF > Telefone > Nome), 4º alfabética.
- Frases rotativas de 1,2 s (FRASES_LEITURA, humorísticas) + barra que NUNCA enche:
  alvo = max(10s, 120% do maior tempo já registrado, persistido em "ocrMaxSeg");
  passa do alvo -> trava em 98% + frase de atraso. Progresso real do Tesseract
  vai só pro console.

SENHA DE ACESSO (accessSecurity.ts + Home.tsx):
- Opcional, 4 caracteres, alfabeto "ABCDEFGHJKLMNPQRSTUVWXYZ123456789" (sem I, O, 0).
- Tela de 4 etapas x 3 caracteres: 12 caracteres distintos; erro NÃO dá feedback
  (só gera novas opções aleatórias); bloqueio por tentativa persistido.
- Sem senha escolhida, o app abre direto (exigência Play Store).
- AVISO: é barreira de discrição, não segurança forte (ver avaliacao-atualizacao-segura.md).

8. ARMADILHAS CONHECIDAS (já deram bug — ver log.txt)

- PowerShell 5.1 lê UTF-8 sem BOM como ANSI: package.json já ganhou BOM (quebrou
  Node) e o Package.appxmanifest já saiu com mojibake ("Clínico" -> "ClÃ­nico"),
  derrubando upload do Partner Center. Sempre gravar UTF-8 SEM BOM ([IO.File]::
  WriteAllText com UTF8Encoding($false)) e conferir bytes.
- Ao MOVER a pasta do projeto, node_modules quebra (junctions apontam pro caminho
  antigo) -> rodar pnpm install.

- PowerShell 5.1 com $ErrorActionPreference = "Stop" trata stderr do Vite/pnpm como
  erro terminante. No msix/build.ps1 a chamada usa `cmd /c "pnpm run build"` para
  não abortar por aviso pré-existente (ocr/tesseract e chunk > 500 kB).
- Vite `--outDir` é relativo ao root do config (client/). Em scripts/build-pages.mjs
  passar caminho absoluto com espaço quebra no CMD; usar `../docs/app`.
- Segredos: o keystore, o log.txt e a senha do build.gradle já entraram no histórico
  uma vez (29/10/2026). Foram removidos do índice e do histórico com git-filter-repo,
  com force-push excepcional e rotação da chave de upload no Play Console. NUNCA
  versionar keystore/properties/log; o build lê android/keystore.properties (ignorado)
  ou variáveis CADCLINICO_*.
- Dev: se um service worker de outra app rodar no servidor de desenvolvimento na porta 3001, ele intercepta
  tudo (já corrigido com o worker auto-remoção).
- Vite avisa que ocr/tesseract.min.js não é module — aviso pré-existente, ignorar.
- Bases antigas sem databaseDate usam updatedAt como fallback; mergeData mantém a
  MENOR data (a data do banco nunca anda para frente).
